# 代码上下文检索

## 推荐调用点与输入

Phase 2 / 3 / 6 / 8。输入为项目根、问题或符号、当前任务 scope。
只分析不修改。检索结果用于理解代码，不能直接判定 gate 通过。

## 工具选择

先探测 PATH 中是否有 `codegraph`，以及项目是否有 `.codegraph/` 索引。
两者都有且能确认检索仅使用本地数据时才启用。
主会话使用可用的本地 MCP `codegraph_explore`；子 agent 使用 CLI。
MCP 不可用时可用本地 CLI。不要为此注册服务或修改配置。
缺少命令、索引、可用接口，或检索要求外部模型服务时，静默回退本地 Grep/Read（如 rg 和文件读取）。
不安装工具、不初始化或更新索引、不调用外部服务。

## 检索方式

| 场景 | 本地 CLI 与结果 |
| --- | --- |
| Phase 2/3 梳理流程 | `codegraph explore "具体流程问题"`，取符号源码和调用链 |
| Phase 3 影响面 | `codegraph impact <symbol> --json`，取调用者与受影响路径 |
| Phase 6 被调方法 | `codegraph node <symbol>`，取签名、实现和必要上下文 |
| Phase 8 改动评审 | `codegraph node <symbol>` 与 `codegraph impact <symbol> --json` |

按工具实际支持的参数执行；不支持时回退，不猜测新选项。
结果已含源码时视为已读，不重复搜索和读取同一处。
结果缺失、与当前改动矛盾或索引已知过期时，针对缺口读取当前源码，并说明证据限制。
回退时先定位符号，再读定义、调用者和相关测试，按问题控制范围。
动态调用和反射无法覆盖的路径标为未知，不把空结果当成零影响。

## 输出与边界

只返回必要源码上下文、`file:line`、调用链和影响结论，不把整仓库内容灌入主会话。
交回调用方，由对应工件写作者摘录到现有 design/spec 或评审报告。
不创建额外 change 工件，不直接编辑 .meta.json 或 retrospective.md。
不自动开启受影响测试裁剪，不以检索结果省略任务要求的测试。
若发现已有结论失效，交回总控回退对应 Phase 并重过验证门。
