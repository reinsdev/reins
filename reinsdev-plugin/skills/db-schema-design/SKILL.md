# 数据模型与迁移设计

输入：同一 change 的 spec.md、proposal、design 或 bugfix-analysis、项目规约。先读 [spec 模板](../spec-driven-dev/templates/spec.md)。编辑范围限 spec 的“数据模型”汇总节及已有 SC 的数据库后置状态。

1. 读取已有 REQ/SC 和“接口契约”，确认实体、事务和一致性要求。保留既有编号、AC 关联、接口字段与 API 行为。
2. 按模板编写“表结构”：表、字段、类型、可空、默认值、含义、关联 SC。业务默认值无用户依据时提出问题，不推断补齐。
3. “索引”说明字段顺序、唯一性、查询用途和关联 SC；“约束”说明主键、外键及其它约束。新增唯一键要说明存量重复数据如何处理。
4. “迁移与回滚”给出正向脚本、回滚脚本、执行顺序、兼容与数据风险、关联 SC。使用项目相对路径和正斜杠；本阶段描述设计，不实际修改数据库或执行 DDL。
5. 在已有 SC 的 AND 中补数据库后置状态：提交、回滚、重复请求、失败后数据不变等。发现 API 行为冲突时交回总控协调 api-design-rest，不覆盖接口章节。
6. 没有数据变更时保留“数据模型”并写“本次不变更”，删除占位行。上游需求有误时交总控回退，不改冻结的工件。

交回总控，由总控跑 gate 3。返回原 spec 路径、补充的 SC 编号、迁移和回滚风险以及尚待确认项。
