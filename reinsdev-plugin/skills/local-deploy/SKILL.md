# 本地部署验收

## 推荐调用点与输入

Phase 8.5，code review 通过且用户已选择本地部署。
接收 change 路径、当前分支、项目 `.openspec/.config.json` 中实际配置的启动命令。
同时确定工作目录、本地 profile、端口、健康检查方式和有界等待时间。
配置缺少这些信息时，从项目已有启动说明或用户给出的命令确认，不发明配置键。
用户已明确选择时不重复确认。未选择或选 n/skip 时交回总控，不启动应用。

## 执行步骤

1. 读取 [deploy-report 模板](../spec-driven-dev/templates/deploy-report.md)，保留全部标题、表头与列顺序。
2. 确认启动命令及其数据库、队列等依赖均为本机资源，不含生产凭据或远程部署操作。
   不下载依赖或镜像，不创建缺失基础设施；缺少本地依赖时报告具体阻碍。
3. 运行已确认的本地启动命令。记录时间、分支、命令、耗时、进程标识与日志相对路径。
   端口被其他进程占用时报告冲突，不终止他人进程。
4. 在确定的超时内检查本次进程状态和项目约定的就绪信号。
   配置了健康检查就必须成功；单凭日志出现 Started 或命令返回 0 不足以证明启动成功。
   健康请求仅发到本机，不跟随远程重定向。
5. 用 log-search 查本次启动窗口的关键错误。启动失败、超时或健康检查失败均记录 failed。
6. 启动成功后提供本机访问地址、待验收场景和停止方式，交用户人工验收。
   未收到用户结论时填“待验收”，不将自动健康检查写成用户认可。

## 报告与交接

只写 change 中既定的 deploy-report.md，不创建其他 change 工件。
运行日志使用项目既有本地日志目录，路径用正斜杠；命令和日志中的秘密先脱敏。
“启动信息”记录实际事实；“启动结果”含 passed/failed、耗时与证据；“错误摘要与日志”含错误或明确的无错误说明。
“用户人工验收结论”只记用户实际反馈，保留验收人、时间和待验收状态。
“结论”按实际启动结果写 passed 或 failed。启动 passed 与用户验收是两个独立事实。
启动失败必须写 failed，交回总控回 Phase 6 修复，禁止改成跳过。
本次创建的失败或临时进程按已记录标识清理。成功后需人工验收时保留本次进程并交代停止方式。

边界：只操作本机应用，不修改业务源码、共享配置，不操作远程环境或外部服务。
不直接编辑 .meta.json 或 retrospective.md，不代替用户设置 uatAccepted、放行或验收。
交回总控，由总控运行 `<spec-driven-dev skill 目录>/scripts/spec-driven gate 8.5 --change <change>`，再组织 Phase 8.9。
